# 城市供排水管网参数化构建平台二期 PRD

文档日期：2026-06-23
适用阶段：二期产品定义与工程闭环设计
目标系统：QP3D 城市供排水管网三维可视化与构建平台
读者：产品、前端、后端、GIS 数据处理、三维构建、数据管理员、项目交付人员

## 1. 背景

一期已经完成城市供排水管网在 Cesium 中的三维可视化基础能力，核心链路为：

1. 从 PostGIS 点表和线表读取数据。
2. 后端 pipeline 解析管线规格、高程、点设施类别。
3. 程序化生成管线和点设施几何。
4. 输出 3D Tiles、metadata、quality-report。
5. 前端加载最新发布版本，支持浏览、拾取、搜索和质量报告查看。

一期的问题也比较明确：当前构建链路仍然强依赖固定表结构和固定字段名，例如线表 `guid`、`qdbm`、`zdbm`、`gg`、`gwlx`，点表 `gdbm`、`lbmc`、`dmbg`、`jgcc`、`jgxz`、`js` 等。实际项目中，不同区县、不同批次、不同测绘成果的数据字段、单位、语义完整度都会变化。如果继续把字段解释写死在代码里，每接入一套数据都要改代码，无法形成可复用的产品。

二期目标是把“写死字段的离线构建工具”升级为“前后端全流程参数化构建平台”。数据管理员可以在前端选择数据源、点线表、字段映射、单位规则、点线自动适配规则和 LOD 参数，保存为构建模板，并通过任务中心触发构建、查看进度、审查质量报告、发布或回滚版本。

本阶段仍以当前参考点表和线表作为默认模板来源，但平台能力必须支持字段可配置和规则可复用。

## 2. 产品目标

二期的核心目标是建立一套可复用、可审查、可追踪的参数化管网构建闭环。

目标：

1. 前端提供构建配置工作台，支持选择数据源、点线表、字段映射、单位、解析规则和构建参数。
2. 后端提供模板管理、字段探测、数据预检查、构建任务、日志、质量报告和版本发布 API。
3. pipeline 从固定字段读取升级为读取构建模板，按模板解释点线数据并生成 3D Tiles。
4. 点设施缺少尺寸、高程、方向、类型等参数时，能够结合相邻管线和拓扑进行自动适配。
5. 构建过程输出结构化适配报告，让用户知道哪些字段来自原始数据，哪些来自推断，哪些使用默认值。
6. 用户可以保存多套构建模板，用于不同数据源、不同项目、不同精度要求的重复构建。
7. 新构建版本必须经过校验后才能发布，失败或质量不达标时不影响线上稳定版本。

非目标：

1. 二期不编辑、不回写源数据库。
2. 二期不做管网在线绘制、增删改和空间编辑。
3. 二期不做水力模拟、流量计算、淹没推演。
4. 二期不要求自动识别所有非标准设施的真实三维模型；模型库和资产管理可以继续按后续阶段扩展。
5. 二期不要求支持任意数据库类型，默认仍以 PostgreSQL/PostGIS 为主。

## 3. 用户与场景

### 3.1 用户角色

数据管理员：

负责接入数据源、配置字段映射、执行预检查、触发构建、审查质量报告、发布版本。

项目交付人员：

负责为不同项目保存构建模板，调整规则参数，输出可验收的三维成果。

运维人员：

关注构建任务是否成功、线上版本是否稳定、是否需要回滚。

业务查看人员：

主要使用 Cesium 可视化成果，不直接参与构建配置。

### 3.2 典型场景

新项目接入：

1. 数据管理员打开构建工作台。
2. 选择 PostGIS 数据源。
3. 选择线表和点表。
4. 系统读取字段、几何类型、SRID、样例值、空值比例、唯一性。
5. 用户选择字段映射和单位规则。
6. 系统执行预检查，展示缺失字段、异常字段、可自动推断项。
7. 用户保存为构建模板并启动构建。
8. 构建完成后查看质量报告和三维预览。
9. 审查通过后发布为最新版本。

同项目增量重建：

1. 用户选择已保存模板。
2. 系统重新探测数据源字段和记录量。
3. 用户确认模板仍匹配当前表结构。
4. 启动构建。
5. 构建成功后生成新版本，可对比上一个版本的记录数、异常数和瓦片体量。

点表参数缺失：

1. 点表只有 `gdbm`、`lbmc`、`geom`、少量 `dmbg`，缺少 `jgcc`、`js`、`jgxz`。
2. 系统通过线表 `qdbm/zdbm` 关联点表 `gdbm`。
3. 根据相邻管线的规格、高程、方向和连接度推断点设施尺寸、节点类型、朝向和合理高程。
4. 推断结果写入质量报告和 metadata，标记为 `inferred`，便于验收追踪。

## 4. 总体方案

二期采用“构建模板 + 预检查 + 构建任务 + 版本发布”的产品架构。

```mermaid
flowchart LR
  A["PostGIS 数据源"] --> B["字段探测 API"]
  B --> C["前端构建配置工作台"]
  C --> D["构建模板"]
  D --> E["数据预检查"]
  E --> F["构建任务队列"]
  F --> G["参数化 pipeline"]
  G --> H["点线自动适配"]
  H --> I["3D Tiles 输出"]
  I --> J["质量报告与适配报告"]
  J --> K["版本校验"]
  K --> L["发布或回滚"]
  L --> M["Cesium 前端加载"]
```

核心设计原则：

1. 字段解释外置为模板，不在 pipeline 中写死项目字段。
2. 构建前必须做预检查，让用户提前知道数据质量和推断风险。
3. 自动适配不能静默覆盖原始数据，必须输出来源和质量标记。
4. 模板要可保存、复制、导入、导出，支持项目复用。
5. 构建任务要可追踪，包含状态、日志、耗时、输入模板、输出版本和失败原因。
6. 发布必须原子化，构建失败或校验失败不能影响当前线上版本。

## 6. 构建模板

### 6.1 模板定位

构建模板是二期的核心产品对象。它描述一套数据如何被解释成管网三维瓦片。

一个模板至少包含：

1. 模板名称、项目名称、说明。
2. 数据源标识。
3. 线表配置。
4. 点表配置。
5. 字段映射。
6. 单位规则。
7. 规格解析规则。
8. 高程和埋深规则。
9. 流向规则。
10. 点线自动适配规则。
11. 点设施模型规则。
12. LOD 和瓦片参数。
13. 输出与发布参数。
14. 质量阈值。

### 6.2 模板状态

模板状态分为：

| 状态 | 说明 |
| --- | --- |
| draft | 草稿，可编辑，不能用于生产发布 |
| validated | 已通过预检查，可启动构建 |
| published | 已用于至少一次发布版本 |
| archived | 已归档，不再作为默认可选模板 |

模板每次保存生成版本号。构建任务必须记录使用的模板版本，保证构建结果可追溯。

### 6.3 模板导入导出

模板支持 JSON 导入导出，便于项目迁移和问题排查。导出内容不包含数据库密码，只包含数据源引用和构建规则。

## 7. 字段映射需求

### 7.1 线表字段

线表字段按语义配置，不要求字段名固定。

| 语义 | 必需 | 当前参考字段 | 说明 |
| --- | --- | --- | --- |
| 线几何 | 是 | `geom` | 必须为 LineString 或可转换为 LineString |
| 管段编码 | 是 | `guid` | 稳定业务 ID |
| 起点编码 | 建议 | `qdbm` | 用于点线拓扑 |
| 终点编码 | 建议 | `zdbm` | 用于点线拓扑 |
| 管网类型 | 建议 | `gwlx` | 雨水、污水、合流、未知 |
| 权属或范围 | 可选 | `gs` | 市政、小区、农村等 |
| 规格或管径 | 建议 | `gg` | 支持数值、DN、宽X高等格式 |
| 材质 | 可选 | `cz` | 用于属性、样式和质量统计 |
| 起点内底标高 | 可选 | `qdndbg` | 高程优先输入之一 |
| 终点内底标高 | 可选 | `zdndbg` | 高程优先输入之一 |
| 起点埋深 | 可选 | `qdms` | 标高缺失时可使用 |
| 终点埋深 | 可选 | `zdms` | 标高缺失时可使用 |
| 流向 | 可选 | `lx` | 当前规则可配置为 `1` 表示起点到终点 |
| 管长 | 可选 | `gdcd` | 可用于校验几何长度 |

如果起终点编码缺失，系统仍可构建管线，但点线自动适配能力会下降，并在质量报告中标记。

### 7.2 点表字段

点表字段同样按语义配置。

| 语义 | 必需 | 当前参考字段 | 说明 |
| --- | --- | --- | --- |
| 点几何 | 是 | `geom` | 必须为 Point 或可转换为 Point |
| 点编码 | 建议 | `gdbm` | 用于关联线表起终点 |
| 点类型 | 建议 | `lbmc` | 井、篦、口、阀门、泵站等 |
| 地面或盖面标高 | 可选 | `dmbg` | 点设施高程输入 |
| 尺寸 | 可选 | `jgcc` | 支持单值、宽X高、混合单位 |
| 形状 | 可选 | `jgxz` | 圆形、矩形、其他 |
| 深度 | 可选 | `js` | 井深或设施深度 |
| 规格 | 可选 | `gg` | 兼容部分项目字段 |
| 材质 | 可选 | `jgcz` | 可用于属性和样式 |
| 口径 | 可选 | `kj` | 可作为尺寸候选 |
| 备注或分类 | 可选 | `tag` | 可用于扩展映射 |

如果点表缺少尺寸、高程或类型，系统通过自动适配补齐可视化参数，但必须保留质量来源。

### 7.3 自定义字段透传

用户可以选择额外字段进入 metadata，用于点击属性面板和搜索。字段透传支持：

1. 原样透传。
2. 字段重命名。
3. 是否进入瓦片 metadata。
4. 是否只保留在后端详情 API。
5. 是否可搜索。
6. 是否可筛选。

敏感字段默认不进入静态瓦片，只能通过后端 API 按权限查询。

## 8. 单位与解析规则

### 8.1 单位配置

模板支持为不同语义字段配置单位：

| 字段类型 | 支持单位 |
| --- | --- |
| 管径/尺寸 | mm、cm、m、自动推断 |
| 标高 | m、cm、mm |
| 埋深 | m、cm、mm |
| 长度 | m、km、自动从几何计算 |
| 角度 | degree、radian |

自动推断必须可解释。例如：

1. `700` 在管径字段中默认按 mm，可解析为 0.7m。
2. `70` 在井盖尺寸中，如果字段规则设为 cm，可解析为 0.7m。
3. `60X60` 在点设施尺寸中，若规则设为 cm，可解析为 0.6m x 0.6m。
4. `140X40` 在篦子尺寸中，若规则设为 cm，可解析为 1.4m x 0.4m。
5. 无法判断单位时使用默认尺寸，并标记 `unit-ambiguous`。

### 8.2 规格解析

规格解析需要支持以下输入：

| 输入类型 | 示例 | 输出 |
| --- | --- | --- |
| 纯数字 | `300` | 圆管直径 300mm |
| DN 前缀 | `DN600` | 圆管直径 600mm |
| 中文混合 | `DN300钢筋砼` | 解析管径 300mm，保留原文 |
| 矩形断面 | `200X300` | 宽 200mm，高 300mm |
| 小写分隔 | `200x300` | 宽 200mm，高 300mm |
| 乘号分隔 | `200×300` | 宽 200mm，高 300mm |
| 空值或 0 | 空、`0` | 使用默认规格，标记异常 |

解析规则应支持项目级覆盖，例如某项目的 `70` 表示 cm，另一项目的 `700` 表示 mm。

## 9. 点线自动适配

点线自动适配是二期的关键能力。它解决当前点数据缺少很多几何参数的问题。

### 9.1 关联策略

优先级如下：

1. 编码关联：线表起点编码、终点编码匹配点表点编码。
2. 几何邻近：编码无法匹配时，使用线几何首末点在一定距离阈值内匹配最近点。
3. 虚拟节点：仍无法匹配时，根据线几何首末点生成虚拟节点。

关联结果写入适配报告：

| 结果 | 标记 |
| --- | --- |
| 编码精确匹配 | `node-match-code` |
| 几何邻近匹配 | `node-match-nearest` |
| 使用虚拟节点 | `node-virtual` |
| 多点冲突 | `node-match-conflict` |

### 9.2 节点类型推断

点类型推断优先级：

1. 使用点表显式类型字段，例如 `lbmc`。
2. 使用点表其他字段中的关键词。
3. 根据连接度推断：
   - 连接度 1：端点、排放口、预留口或断点候选。
   - 连接度 2：双通、普通连接、弯头候选。
   - 连接度 3：三通候选。
   - 连接度 4：四通候选。
   - 连接度大于 4：复杂节点候选。
4. 根据相邻管线夹角推断弯头。
5. 根据相邻管线规格变化推断变径点。
6. 根据相邻管线材质变化推断变材点。

如果显式点类型和拓扑推断冲突，默认以显式字段为主，同时在报告中记录 `node-type-conflict`。

### 9.3 点设施尺寸推断

点设施尺寸来源优先级：

1. 点表尺寸字段，例如 `jgcc`、`kj`、`gg`。
2. 点表形状字段，例如 `jgxz`。
3. 相邻管线最大管径或最大断面尺寸。
4. 点类型默认尺寸。
5. 全局默认尺寸。

建议默认规则：

| 点设施 | 默认可视化尺寸 |
| --- | --- |
| 井盖圆形 | 0.7m 直径 |
| 雨篦/污篦 | 0.6m x 0.4m |
| 进水口/排放口 | 0.8m x 0.5m |
| 双通/三通/四通 | 根据相邻管线最大外径加缓冲 |
| 弯头 | 根据相邻管线外径和夹角生成 |
| 变径点 | 根据两侧管径生成渐变接头或符号 |
| 未知点 | 0.6m 低模点符号 |

尺寸来源需要写入 metadata：

| 来源 | 标记 |
| --- | --- |
| 原始字段解析 | `point-size-source-field` |
| 从线推断 | `point-size-source-connected-line` |
| 类型默认 | `point-size-source-type-default` |
| 全局默认 | `point-size-source-global-default` |

### 9.4 点设施高程推断

点设施高程来源优先级：

1. 点表地面或盖面标高字段。
2. 与点关联的相邻管线端点内底标高，加井室或盖面推断偏移。
3. 管线埋深字段结合地面标高策略推断。
4. 邻近点或同片区中位地面标高。
5. 全局默认地面标高。

井/篦的三维锚点应区分：

1. 盖面或篦面：贴近地面标高，不从地面往上长出数米。
2. 井筒或地下体：从盖面向下延伸，近景可显示。
3. 连接口：尽量对齐相邻管线中心线或内底标高。

高程来源标记：

| 来源 | 标记 |
| --- | --- |
| 点表标高 | `point-height-source-field` |
| 线端点推断 | `point-height-source-connected-line` |
| 邻近统计推断 | `point-height-source-neighbor` |
| 默认值 | `point-height-source-default` |

### 9.5 朝向与连接方向

管件朝向来源：

1. 单连接点使用相邻管线方向。
2. 双连接点使用两条相邻管线方向，若夹角明显则生成弯头。
3. 三通、四通使用所有相邻管线方向生成连接臂。
4. 雨篦、进水口如缺少朝向，优先沿最近道路或相邻管线方向，若没有道路数据则按相邻管线方向。

二期不要求所有朝向都真实准确，但必须避免全部管件固定朝向导致明显错误。

## 10. 构建配置工作台

### 10.1 数据源与表选择

页面能力：

1. 展示可用数据源。
2. 测试数据库连接。
3. 列出 schema、表名、记录量、几何字段。
4. 识别点表、线表候选。
5. 展示 SRID、几何类型、字段列表、样例值。

用户选择：

1. 线表。
2. 点表。
3. 是否启用点线关联。
4. 是否允许虚拟节点。
5. 输出版本命名规则。

### 10.2 字段映射向导

字段映射向导按步骤组织：

1. 基础字段：几何、编码、点类型、管段编码。
2. 拓扑字段：起点编码、终点编码。
3. 分类字段：管网类型、权属、材质。
4. 规格字段：管径、断面、点尺寸、点形状、深度。
5. 高程字段：内底标高、埋深、地面标高。
6. 流向字段：流向值和方向规则。
7. 透传字段：进入属性面板、搜索和筛选的字段。

系统应根据字段名、样例值和数据类型给出推荐映射，例如：

| 字段名 | 推荐语义 |
| --- | --- |
| `guid` | 管段编码 |
| `qdbm` | 起点编码 |
| `zdbm` | 终点编码 |
| `gdbm` | 点编码 |
| `lbmc` | 点类型 |
| `gg` | 管径或规格 |
| `jgcc` | 点设施尺寸 |

推荐映射必须允许用户覆盖。

### 10.3 单位与规则配置

页面能力：

1. 为每类字段选择单位。
2. 配置规格解析模式。
3. 配置无法解析时的默认值。
4. 配置异常阈值，例如管径小于 50mm 或大于 5000mm 时标记异常。
5. 配置流向规则，例如 `lx=1` 表示起点到终点，其他值表示终点到起点。
6. 配置点设施默认尺寸表。
7. 配置高程优先级。

### 10.4 自动适配配置

页面能力：

1. 启用或关闭编码关联。
2. 配置几何邻近匹配距离。
3. 配置连接度到节点类型的映射。
4. 配置尺寸推断规则。
5. 配置高程推断规则。
6. 配置冲突处理策略。
7. 展示抽样适配结果。

冲突处理策略：

| 策略 | 说明 |
| --- | --- |
| prefer-point-field | 显式点字段优先 |
| prefer-topology | 拓扑推断优先 |
| report-only | 不覆盖，只报告冲突 |

默认推荐 `prefer-point-field`。

### 10.5 LOD 与输出配置

页面能力：

1. 配置单 tile 最大 feature 数。
2. 配置单 tile 目标体量。
3. 配置最大分裂深度。
4. 配置管线径向段数。
5. 配置远中近 LOD 模型策略。
6. 配置是否输出点设施、管线、异常数据独立 tileset。
7. 配置是否输出 aggregate metadata。
8. 配置输出目录和版本名称。

默认建议：

| 参数 | 默认值 |
| --- | --- |
| 单 tile 最大 feature 数 | 2000 |
| 单 tile 目标体量 | 4MB |
| 最大分裂深度 | 8 |
| 普通管线径向段数 | 12 |
| 远景管线 | 简化线或低段数管 |
| 点设施远景 | 低模或图标 |

## 11. 预检查

预检查在构建前执行，目的是避免用户等到构建结束才发现字段映射错误。

预检查内容：

1. 表是否存在。
2. 几何字段是否存在。
3. 几何类型是否符合点表和线表要求。
4. SRID 是否一致。
5. 记录量统计。
6. 编码字段空值率。
7. 编码重复率。
8. 起终点编码可匹配率。
9. 规格字段可解析率。
10. 高程字段覆盖率。
11. 点尺寸字段覆盖率。
12. 点线几何距离异常。
13. 预计 tile 数量和构建体量。

预检查结果分为：

| 等级 | 含义 |
| --- | --- |
| error | 阻止构建，例如无几何字段、表不存在 |
| warning | 允许构建，但需要用户确认，例如尺寸字段大量缺失 |
| info | 普通提示，例如自动推断覆盖率 |

用户必须确认 warning 后才能启动构建。

## 12. 构建任务中心

构建任务状态：

| 状态 | 说明 |
| --- | --- |
| queued | 已提交，等待执行 |
| inspecting | 正在探测字段和数据 |
| preprocessing | 正在归一化与自动适配 |
| tiling | 正在生成几何和瓦片 |
| validating | 正在校验输出 |
| completed | 构建完成，未发布 |
| published | 已发布 |
| failed | 构建失败 |
| canceled | 用户取消 |

任务详情展示：

1. 任务 ID。
2. 使用的模板版本。
3. 数据源和表名。
4. 提交人和提交时间。
5. 当前阶段和进度。
6. 日志。
7. 质量报告。
8. 适配报告。
9. 输出版本。
10. 发布操作。

任务取消规则：

1. queued、inspecting、preprocessing 阶段可以直接取消。
2. tiling 阶段取消后需要清理 staging 输出目录。
3. validating 阶段取消后不发布版本。
4. 已发布版本不能取消，只能回滚到其他版本。

## 13. 质量报告与适配报告

### 13.1 质量报告

质量报告继续包含一期已有内容，并新增二期参数化统计：

1. 模板 ID 和模板版本。
2. 字段映射摘要。
3. 单位配置摘要。
4. 总记录数、成功数、跳过数。
5. 规格解析成功率。
6. 点尺寸解析成功率。
7. 点高程解析成功率。
8. 点线编码匹配率。
9. 几何邻近匹配率。
10. 虚拟节点数量。
11. 默认值使用数量。
12. 质量阈值是否通过。
13. 输出 tile 数量、最大 tile 大小、平均 tile 大小。

### 13.2 适配报告

适配报告聚焦“系统怎么补全数据”：

| 项 | 内容 |
| --- | --- |
| 点类型来源 | 原字段、拓扑推断、默认 |
| 点尺寸来源 | 原字段、线推断、类型默认、全局默认 |
| 点高程来源 | 原字段、线推断、邻近推断、默认 |

适配报告应可在前端按类型过滤，也应可导出为 JSON 或 CSV。

## 15. Pipeline 参数化设计

pipeline 二期需要从固定函数参数升级为读取构建模板。

核心模块：

| 模块 | 责任 |
| --- | --- |
| template-loader | 读取并校验构建模板 |
| field-mapper | 按模板把源表行映射为标准中间结构 |
| unit-normalizer | 处理单位、尺寸、标高、埋深 |
| spec-parser | 解析管径和断面 |
| topology-builder | 建立点线拓扑 |
| point-adapter | 推断点设施类型、尺寸、高程、朝向 |
| geometry-builder | 生成管线和点设施 mesh |
| tile-builder | 生成 LOD 和 3D Tiles |
| report-writer | 输出质量报告和适配报告 |
| version-publisher | 发布和回滚版本 |

标准中间结构建议：

```ts
interface NormalizedPipeLine {
  sourceId: string
  startNodeId?: string
  endNodeId?: string
  geometry: LineString
  pipeType?: string
  owner?: string
  material?: string
  spec?: ParsedPipeSpec
  startInvertElevation?: number
  endInvertElevation?: number
  startDepth?: number
  endDepth?: number
  flowDirection?: 'start-to-end' | 'end-to-start'
  rawProperties: Record<string, unknown>
}

interface NormalizedPointFacility {
  sourceId?: string
  geometry: Point
  pointType?: string
  surfaceElevation?: number
  size?: ParsedPointSize
  shape?: 'round' | 'rect' | 'unknown'
  depth?: number
  rawProperties: Record<string, unknown>
}
```

标准结构只表达语义，不绑定源表字段。

## 16. 3D 表达要求

二期三维表达需要解决当前井和篦大小、高低不合理的问题。

管线：

1. 继续基于线几何和规格程序化生成。
2. 管径、断面、材质、流向颜色由模板字段映射决定。
3. 支持雨水管、污水管、合流管、未知管类型配色。
4. 支持流向动态材质。
5. 支持 LOD 分块和 tile 级 metadata。

点设施：

1. 使用参数化点规格，不再按类别固定 3m 或 4m。
2. 井盖/篦面应贴近地表或盖面标高。
3. 井筒向下生成，深度来自 `js` 或相邻管线推断。
4. 弯头、双通、三通、四通应根据拓扑方向生成，不固定为同一朝向。
5. 消防栓、闸门、泵站等可继续支持模型库扩展。

LOD：

1. 保留一期已完成的空间分块。
2. 二期进一步支持近中远模型策略。
3. 远景点设施可用低模或图标。
4. 近景才显示井筒、连接件细节。
5. 单 tile 体量继续控制在 1-5MB 目标范围。

## 17. 权限与安全

安全原则：

1. 数据库连接信息只在后端配置，不暴露给前端。
2. 前端只能看到数据源名称、表结构和字段样例，不展示数据库密码。
3. 模板导出不包含密钥。
4. 构建任务日志不得输出数据库密码。
5. 发布版本前必须校验输出目录，避免写出到非预期路径。
6. 静态瓦片中的 metadata 字段可控，敏感字段默认只通过后端详情 API 查询。

权限建议：

| 权限 | 能力 |
| --- | --- |
| viewer | 查看已发布版本和质量报告 |
| builder | 创建模板、启动构建、查看任务 |
| publisher | 发布和回滚版本 |
| admin | 管理数据源和系统配置 |

## 19. 验收标准

产品验收：

1. 用户可以在前端完成从数据源选择到版本发布的完整流程。
2. 用户可以保存并复用构建模板。
3. 用户可以为点表和线表选择字段映射。
4. 用户可以配置单位和默认规则。
5. 用户可以执行预检查并看到 error、warning、info。
6. 用户可以启动构建任务并查看任务状态和日志。
7. 用户可以查看质量报告和适配报告。
8. 用户可以发布构建版本，并在 Cesium 前端加载新版本。

数据适配验收：

1. 点表缺少尺寸字段时，系统能按相邻线规格或默认规则生成合理尺寸。
2. 点表缺少高程字段时，系统能按相邻线端点或默认规则生成可解释高程。
3. 点类型缺失或不完整时，系统能按连接度识别双通、三通、四通、弯头等候选。
4. 所有推断结果都在报告中标记来源。
5. 原始字段和推断结果冲突时，报告中能看到冲突项。

技术验收：

1. pipeline 不再依赖固定字段名完成 PostGIS 构建。
2. 构建模板有自动化测试覆盖。
3. 字段映射、单位解析、点线适配、质量报告均有测试覆盖。
4. 构建失败不影响当前已发布版本。
5. 发布版本可回滚。
6. API 不暴露数据库连接密钥。
7. 3D Tiles 输出仍可被 CesiumJS 1.117 正常加载。

## 21. 风险与约束

1. 不同项目字段语义差异很大，自动推荐映射不能完全替代人工确认。
2. 点线编码可能不一致，几何邻近匹配需要距离阈值和冲突报告，否则容易误匹配。
3. 点设施尺寸字段存在 mm、cm、m 混用，自动单位推断必须保守。
4. 点高程语义可能是地面标高、盖面标高或其他标高，必须允许模板中配置语义。
5. 如果缺少道路、地形或地面高程数据，部分雨篦朝向和盖面高程只能近似推断。
6. 构建任务可能耗时较长，需要后台任务和 staging 目录清理机制。
7. 过多字段进入瓦片 metadata 会增大 tileset 或 GLB 体量，需要字段透传控制。
8. 前端构建工作台复杂度较高，需要优先保证字段映射、预检查、任务中心三条主线。
